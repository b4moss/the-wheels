## TwFilePond

- クラス `TwFilePond`、タグ `tw-file-pond`、`data-tw-component="file-pond"`
- イベント（既定）: `tw-add` / `tw-remove` / `tw-reject`
- `detail` は `{ file?: File, reason?: "max-files" | "max-size" | "accept" }`

### TwFilePond（選択）

- 内部の hidden `<input type="file" multiple>` でファイルを選ぶ
- 通過したファイルだけ `files` に載せる
- クリック操作で input の選択ダイアログ相当が使える（テストは input への File 設定で代替してよい）

#### テスト：正常系
- 1件選ぶと `files.length` が 1 になり、`add` が 1 回発火する
- 複数件まとめて選ぶと、通過した件数だけ `files` に載り、件数分 `add` が発火する
- 選んだファイルの `name` / `size` / `type` が `files` の各要素と一致する

#### テスト: 異常系
- 空の選択（ファイル 0 件）では `files` は空のまま、`add` / `reject` は発火しない
- 同じ input で続けて選んでも例外なく `files` が追従する
- 選択操作でページが落ちない

### TwFilePond（DnD）

- ドロップ領域への DnD でファイルを受け取れる
- フォルダ DnD は無視する（ファイルだけ）

#### テスト：正常系
- ファイルをドロップすると `files` に載り、`add` が発火する
- 複数ファイルのドロップで、通過した件数だけ載る
- クリック選択と DnD を混ぜても `files` は累積する（上限内）

#### テスト: 異常系
- フォルダ相当のエントリをドロップしても `files` に載せず、例外なし
- ファイルを含まない drop では `files` は変わらない
- drop 処理中に例外を投げない

### TwFilePond（max-files）

- 属性 `max-files` は正の整数。未指定は件数制限なし
- 上限を超える分は載せない。超えた各ファイルについて `reject`（`reason: "max-files"`）を出す

#### テスト：正常系
- `max-files="2"` で 2 件まで `files` に載る
- 上限ちょうどでは `reject` は出ない
- 未指定なら 3 件以上でも載る

#### テスト: 異常系
- 上限到達後の追加は `files` が増えず、`reject` の `reason` が `"max-files"`
- `max-files="0"` や不正値は制限なしとして扱い、例外を投げない
- 上限超過のファイルはリストに出ない

### TwFilePond（max-size）

- 属性 `max-size` はバイト単位の整数。未指定は容量制限なし
- 超過ファイルは載せない。`reject`（`reason: "max-size"`）を出す

#### テスト：正常系
- `max-size` 以下のファイルは `files` に載り `add` が発火する
- 未指定なら大きなファイルも載る
- 複数件のうち超過分だけ拒否し、未満は載る

#### テスト: 異常系
- `size` が `max-size` を超えるファイルは載せず、`reason` が `"max-size"`
- 不正な `max-size` は制限なしとして扱い、例外を投げない
- 拒否したファイルのプレビューは出ない

### TwFilePond（accept）

- 属性 `accept` は `<input accept>` と同じカンマ区切り MIME（および `image/*` のような型トークン）
- 未指定は MIME 制限なし
- 不一致は載せない。`reject`（`reason: "accept"`）を出す

#### テスト：正常系
- `accept="image/png"` で PNG は載る
- `accept="image/*"` で JPEG など画像は載る
- 未指定なら `text/plain` も載る

#### テスト: 異常系
- `accept="image/png"` で `text/plain` は載せず、`reason` が `"accept"`
- 空の `accept` は制限なしとして扱う
- 不一致ファイルのプレビューは出ない

### TwFilePond（プレビュー）

- 画像 MIME のみサムネイル（blob URL）を出す
- それ以外はファイル名とサイズを出す
- `remove` / `clear` 時に blob URL を revoke する

#### テスト：正常系
- 画像ファイルを入れるとプレビュー用の画像要素（または同等）が見える
- 非画像は名前とサイズが見え、サムネイル画像は出ない
- 画像と非画像が混在しても、画像側だけサムネイルになる

#### テスト: 異常系
- PDF など非画像を入れてもサムネイルにしない（1枚目プレビューは対象外）
- 削除後にプレビューが消える
- blob URL は削除後に revoke される（再利用できない）

### TwFilePond.add / remove / reject

- 通過時は `add`、削除時は `remove`、検証失敗時は `reject`
- `setPrefix` 後はイベント名が接頭辞に追従する

#### テスト：正常系
- 追加で `add` が飛び、`detail.file` がある
- `removeAt` で `remove` が飛び、`detail.file` がある
- 接頭辞 `app-` のときイベント名は `app-add` などになる

#### テスト: 異常系
- 検証失敗では `add` は出さず `reject` だけ出す
- 空リストに対する `removeAt` では `remove` を出さない
- イベントリスナが例外を投げてもホストが操作可能である（可能なら。過度に追わない）

### TwFilePond.removeAt / clear / files

- `files` は読み取り用の `File[]`
- `removeAt(index)` で 1 件削除
- `clear()` で全削除

#### テスト：正常系
- `files` は現在保持している File の配列である
- `removeAt(0)` で先頭が消え、残りがずれて残る
- `clear()` で `files` が空になる

#### テスト: 異常系
- 範囲外の `removeAt` は `files` を変えず、例外を投げない
- 空の状態で `clear()` しても例外なし
- 削除後に同じファイルを再度追加できる

## TwExpandable

- クラス `TwExpandable`、タグ `tw-expandable`、`data-tw-component="expandable"`
- 内容は slot。折りたたみ中も DOM に残し、領域内スクロール
- 下部に WC 内蔵のトグルボタン
- 属性 `collapsed-height` / `expanded-height`（CSS の長さ。`expanded-height` 未指定または空は内容高さ相当）
- トグル文言は属性で上書き可（名称は実装時固定。例: `expand-label` / `collapse-label`）

### TwExpandable（開閉）

- トグルで折りたたみ ↔ 展開を切り替える

#### テスト：正常系
- 初期は折りたたみ相当の高さで、内容スロットが存在する
- トグル 1 回で展開状態になる（展開を示す属性または同等の状態）
- もう一度トグルすると折りたたみに戻る

#### テスト: 異常系
- 連続トグルしても例外なく状態が追従する
- 内容が空でもトグルで落ちない
- 折りたたみ中もスロット内容が DOM から消えない

### TwExpandable（高さ・文言）

- `collapsed-height` / `expanded-height` を反映する
- 文言上書き属性があるとき、トグルボタンの表示文言がそれに従う

#### テスト：正常系
- `collapsed-height` 指定時、折りたたみ状態のボックス高さがその指定に従う（厳密 px 一致は求めず、指定が効いていること）
- `expanded-height` 未指定では展開時に内容が見切れることなくスクロールまたは内容高で見える
- 文言上書き属性を付けるとボタン表示が変わる

#### テスト: 異常系
- 不正な高さ文字列でも例外を投げず、開閉できる
- 文言属性を外すと既定文言（または空でないラベル）に戻る
- `prefers-reduced-motion` 相当でも開閉操作自体は完了する（時間の数値は見ない）

## TwStepNav

- クラス `TwStepNav`、タグ `tw-step-nav`、`data-tw-component="step-nav"`
- 表示のみ。パネル・次へ／戻る・クリック遷移なし
- 各ステップに `status` = `current` | `done` | `not_yet`（属性名は実装時固定）
- `setCurrent(index)` は指定インデックスを `current` にするだけ。他ステップの `done` / `not_yet` は自動付け替えしない

### TwStepNav（表示）

- ステップのラベル／番号／`status` が見える

#### テスト：正常系
- 複数ステップを置くと、それぞれの `status` が反映される
- `current` のステップが識別できる（属性または同等）
- `done` / `not_yet` もそれぞれ区別できる

#### テスト: 異常系
- ステップ 0 件でも例外なく接続できる
- 不明な `status` 値でもホストが落ちない（無視または既定にフォールバック）
- ステップをクリックしても `status` は変わらない

### TwStepNav.setCurrent

- 指定インデックスを `current` にする
- 他ステップの status は触らない

#### テスト：正常系
- `setCurrent(1)` で index 1 が `current` になる
- 呼び出し前に `done` だった他ステップは `done` のまま
- 呼び出し前に `not_yet` だった他ステップは `not_yet` のまま

#### テスト: 異常系
- 範囲外 index ではどの `status` も変えず、例外を投げない
- 連続で異なる index を指定しても例外なく追従する
- 負の index でも落ちない

## TwPagination

- クラス `TwPagination`、タグ `tw-pagination`、`data-tw-component="pagination"`
- 属性 `page`（1-based）、`total-pages`（正の整数）
- prev / next とページ番号 UI
- 変更時は `getEventName("change")`（既定 `tw-change`）、`detail.page` は 1-based
- 件数セレクト・サーバ通信は持たない

### TwPagination（表示・移動）

- 現在ページと総ページに応じて UI を出す

#### テスト：正常系
- `page="1"` `total-pages="5"` で 1 ページ目として表示される
- next 相当操作で `page` が 2 になり、`change` が `detail.page === 2` で発火する
- ページ番号クリックでそのページへ移り、`change` が発火する

#### テスト: 異常系
- `page` が `total-pages` のとき next しても `page` は変わらず、不要な `change` は出さない（または出しても同じ page）
- `page="1"` のとき prev しても 1 のまま
- 不正な `page` / `total-pages` でも例外なく描画できる（フォールバック）

### TwPagination.change / 接頭辞

- `setPrefix` 後はイベント名が追従する

#### テスト：正常系
- ページ変更で `change` が 1 回以上飛び、`detail.page` がある
- 接頭辞 `app-` のときイベント名は `app-change` になる
- `page` 属性をスクリプトで変えると表示が追従する

#### テスト: 異常系
- `total-pages="1"` では prev/next しても page は 1 のまま
- リスナが例外を投げてもホストが操作可能（可能なら）
- `page` を範囲外にセットしても落ちない

## TwTabs（change 追加）

- 現行 API（`selected-index` / `select` / slots）は維持
- 選択が変わったとき `getEventName("change")`（既定 `tw-change`）、`detail.selectedIndex`（0-based）を発火する
- ユーザー操作と `select(index)` の両方で発火する

### TwTabs.change

- 選択変更の通知

#### テスト：正常系
- 別タブをクリックすると `change` が飛び、`detail.selectedIndex` が新しい index になる
- `select(2)` でも同様に `change` が飛ぶ
- 接頭辞 `app-` のときイベント名は `app-change` になる

#### テスト: 異常系
- すでに選ばれているタブを再度選んでも、不要に連続 `change` しない（同じ index では発火しない）
- 範囲外の `select` では選択が変わらず、`change` も出さない（または現行どおりフォールバック。いずれにせよ例外なし）
- 既存の `selected-index` 属性同期は壊れない

## TwToast

- クラス `TwToast`、タグ `tw-toast`、`data-tw-component="toast"`
- `createSnackbarLayer` 上に載せる（CookieConsent の単一バナー利用を壊さない）
- 属性 `variant` = `info` | `success` | `warning` | `error`（不正値は `info` 相当）
- 属性 `duration-ms`（既定 `4000`。`0` で自動消去なし）
- メソッド `show()` / `hide()`
- 同一レイヤ内で複数表示可。新着を下にスタック

### TwToast（表示・消去）

- 表示と手動／自動消去

#### テスト：正常系
- `show()` でトースト内容が見える
- `hide()` で非表示になる
- `duration-ms="0"` では時間経過だけでは消えない

#### テスト: 異常系
- 二重に `show()` しても例外なく表示状態を保てる
- 非表示時に `hide()` しても例外なし
- 不正な `variant` でも表示でき、落ちない

### TwToast（自動消去・スタック）

- 正の `duration-ms` で自動消去
- 複数同時のスタック

#### テスト：正常系
- `duration-ms` 経過後に非表示になる（実時間は fake timer でよい。アニメ完了は待たない）
- 2 件 `show` すると両方見える（スタック）
- 片方を `hide` しても他方は残る

#### テスト: 異常系
- CookieConsent 用レイヤの既存利用を壊さない（Consent デモまたは層 API の単体で、Toast 追加後も show/hide 可能）
- 自動消去タイマー中に `hide()` しても例外なし
- 破棄後の `show()` は落ちないか、ノーオペになる（実装方針に合わせ、例外を投げない）

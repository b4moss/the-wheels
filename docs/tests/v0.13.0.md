# v0.13.0 テスト仕様

対象: Playwright による kitchen-sink 上の E2E（Chromium）。  
Vitest でカバー済みの単体分岐は重複させない。スタイルのピクセル一致・自動 VRT・a11y 本検討は対象外。

関連: [plans/v0.13.0](../plans/v0.13.0/playwright-e2e.md) / [test.md](../test.md) / [dropdown.md](../specs/components/dropdown.md) / [action_menu.md](../specs/components/action_menu.md) / [user_menu.md](../specs/components/user_menu.md) / [modal.md](../specs/components/modal.md) / [combobox.md](../specs/components/combobox.md) / [infinite_scroll.md](../specs/components/infinite_scroll.md) / [cookie_consent.md](../specs/components/cookie_consent.md)

計画上の補足（完了定義）:

- 実行環境: Playwright + kitchen-sink。ローカルは **`dev`**、CI は **`preview`**。ブラウザは **Chromium のみ**（本版）
- セレクタは `data-tw-component` とデモの安定 ID／`data-tw-*` を優先。文言マッチは最小限
- Floating UI: 座標の厳密一致はしない。`getBoundingClientRect` 等で **viewport 内に収まる／大きくはみ出さない／開閉可能** を検証
- Floating UI 用に kitchen-sink へフィクスチャページ（例: `/dropdown-placement/`）を用意する（四隅・中央＋複数 `placement`）
- **含まない**: HTTP 200 / ナビ横断 smoke、Storybook play/interaction、自動 VRT、a11y 本検討
- アサートは **振る舞いのみ**（表示／非表示、開閉、件数の増減、storage の状態）。色・px・アニメ完了待ちは入れない（スタイル改修で壊れないようにする）

## 開閉系（overlays）

対象ページは既存 kitchen-sink（`/modal/`、`/action-menu/`、`/user-menu/` 等）。Accordion / Tabs は代表を1本入れてよい（必須は Modal + ActionMenu または UserMenu）。

### Modal

#### 正常系

- 開く操作で dialog／モーダル内容が表示される
- 閉じる（× または同等）で非表示になる
- バックドロップ相当の操作で閉じる（デモが提供している場合）

#### 異常系

- 既に閉じている状態で閉じ操作 → 例外なく閉じたまま
- 開いたままページ遷移しなくても状態が壊れない（同一ページ内の再オープン可）

### ActionMenu / UserMenu

#### 正常系

- trigger クリックで panel が開く（`open` 属性または可視 panel）
- 外側クリックで閉じる
- `Escape` で閉じる
- panel 内の項目クリックで閉じる

#### 異常系

- 閉じた状態で `Escape` → 何も壊れない
- 開いた状態で再度 trigger → 閉じる（toggle）

### Accordion または Tabs（代表1本・任意だが推奨）

#### 正常系

- Accordion: ヘッダ操作で領域が開閉する
- または Tabs: タブ切替で表示パネルが変わる

#### 異常系

- 連続クリックしても例外なく状態が追従する

## Floating UI（手厚く）

フィクスチャページ（例: `/dropdown-placement/`）を前提とする。

### 配置フィクスチャ

#### 正常系

- トリガーが **中央 / 上端付近 / 下端付近 / 左端付近 / 右端付近** にそれぞれ存在する
- 各トリガーから Dropdown（または ActionMenu）を開ける

#### 異常系

- フィクスチャ欠落時はテストを skip せず、ページ追加を必須とする（本仕様の前提）

### placement と viewport 内収まり

少なくとも次の `placement` を検証する: `bottom-start`、`top-end`、`left-start`、`right-end`（不足はフィクスチャ側で追加）。

#### 正常系

- 各 placement（または端トリガー）で開いた panel の矩形が、ビューポート矩形に対して **大きくはみ出さない**（許容: 実装で固定。例: 各辺のはみ出しが 8px 未満、または交差面積が panel 面積の大半）
- 端付近では flip / shift 後も **開閉・項目クリックが可能**
- 閉じたあと再オープンしても再び収まって見える

#### 異常系

- 不正な `placement` 属性のデモがある場合 → 開閉でき、viewport 内に収まる（フォールバック動作）
- 連続で異なる端のトリガーを開閉しても例外なし

### 代表コンポーネントへの適用

#### 正常系

- Dropdown 本体に加え、ActionMenu または UserMenu の少なくとも1つが端フィクスチャで同様に収まる

## Combobox

対象: `/combobox/`（既存デモ）。

### static

#### 正常系

- 開くと検索欄とオプションが見える
- 検索入力で表示件数が減る（一致なしなら空状態）
- オプション選択で選択表示／value 表示が更新される（デモの表示要素）

#### 異常系

- 空クエリに戻すと件数がある状態に戻る
- 無効な操作（disabled デモがある場合は選択できない）で例外なし

### async

#### 正常系

- 開いた直後、リストの **先頭側** が見える（末尾だけが見えている状態にならない）
- 下端付近までスクロールすると件数が増える（追加ロード）

#### 異常系

- 開閉を繰り返しても先頭表示が破綻しない（末尾ジャンプの回帰防止）

### hybrid（推奨）

#### 正常系

- 開くとリストが見え、先頭側が表示される
- 検索またはスクロールが例外なく動作する

## InfiniteScroll

対象: `/infinite-scroll/`。

#### 正常系

- 初期にリスト項目が表示される
- 下端スクロールで件数が増える

#### 異常系

- 上端／下端の連続スクロールでも例外なく完了する（件数が減らない・増えすぎてページが落ちない程度の健全性）

## CookieConsent

対象: `/cookie-consent/`。各シナリオ前にデモのリセット（または `localStorage` クリア＋リロード）で初期化する。

### 初回表示

#### 正常系

- バナー（下部）が表示される
- localStorage（既定キーまたはデモキー）に JSON があり、`status` が `pending` 相当

#### 異常系

- リセット後に再訪相当（リロード）してもバナーが出る

### すべて承諾

#### 正常系

- 「すべて承諾」でバナーが消える
- storage の `status` が `accepted`
- `service-ids` 対象のサービスがすべて `true`（デモのチェックがすべて ON）

#### 異常系

- 承諾後にリロードしてもバナーは出ない（期限内・`bannerHidden`）

### サービス別

#### 正常系

- 1つ以上 ON → `status` が `partial`（またはデモ JSON 上そう見える）
- すべて OFF → `status` が `rejected`
- JSON 表示（デモの textarea）がチェック操作に追従する

#### 異常系

- Apply で不正 JSON を入れてもページが落ちない（デモのエラー表示または無視）。チェック状態が壊れても例外スローしない

### 設定する

#### 正常系

- 「設定する」でバナーが消える
- `status` は `pending` のまま（全体承諾にならない）
- `bannerHidden` が true 相当

## CI・実行

#### 正常系

- `npm run test:e2e`（名称は実装で固定）で本仕様のシナリオが実行できる（ローカルは kitchen-sink `dev`）
- CI の **`e2e` ジョブ**で Playwright（Chromium）が走る。対象は kitchen-sink **`preview`**。失敗でそのジョブは落ちる
- 変更パスがすべて `docs/**` または `*.md`（ルートの `README.md` 含む）なら `e2e` をスキップする
- required check は当面 `verify`。`e2e` を required にするタイミングは PO（[git.md](../git.md)）

#### 異常系

- フレーク対策: 必要なら `expect` の auto-wait／明示 wait を使う。固定 `waitForTimeout` の多用は避ける

## 対象外（この版の自動テストに含めない）

- kitchen-sink 全ページの HTTP 200 / ナビ横断 smoke
- Storybook play / interaction / 自動 VRT
- CSS の色・影・フォントのピクセル一致
- Floating UI の「期待 placement どおりのピクセル座標」厳密一致
- Firefox / WebKit（本版は Chromium のみ）
- a11y 本検討
- npm 公開

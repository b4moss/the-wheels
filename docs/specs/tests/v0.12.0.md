# v0.12.0 テスト仕様

> 状態: **済・現行**。workspace version は **0.12.0**（npm 未公開）。

対象: `TwUserMenu`、`TwCookieConsent`、および Snackbar レイヤ（共有モジュール。公開面の名称は実装で固定）。  
スタイル（CSS）の自動テストは行わない。カスタムイベントは発火しない（総則どおり。遷移は `href`／メソッドで足りる）。

関連仕様: [all.md](../components/all.md) / [user_menu.md](../components/user_menu.md) / [cookie_consent.md](../components/cookie_consent.md) / [snackbar_layer.md](../components/snackbar_layer.md) / [dropdown.md](../components/dropdown.md) / [action_menu.md](../components/action_menu.md)  
roadmap: [roadmap.md](../../roadmap.md)（v0.12.0）

計画上の補足（完了定義）:

- UserMenu は内部に現接頭辞の Dropdown を合成する。ActionMenu は使わない（兄弟）
- 推奨項目マーカーは `data-tw-user-menu-item`（接頭辞変更後も `data-tw-*` 固定）
- CookieConsent の localStorage 既定キーは `tw-cookie-consent`。JSON フィールドは少なくとも `status`（`pending` | `accepted` | `partial` | `rejected`）、`bannerHidden`（boolean）、`services`（object）、`expiresAt`（ISO 文字列を推奨）
- `status` 再計算: サービス別 API でキーが1つ以上ありいずれか true → `partial`、すべて false → `rejected`。一括承諾は `accepted` かつ `service-ids` をすべて `true` で埋める
- `ttl-days` 未指定は `365`。スライディング延長は接続時の有効判定で行う
- 「すべて承諾」「設定する（バナー非表示）」はホストメソッドまたは `data-tw-*` 委譲でテスト可能にする（slot 内ボタンから呼べること）
- Toast WC・チェックボックス設定 UI・Playwright E2E・a11y 本検討は対象外

## Snackbar レイヤ（共有）

実装名は問わない（例: `createSnackbarLayer` / `TwSnackbarLayer`）。packages から再利用できること。

### show / hide と配置

- コンテンツを viewport **下部**に表示／非表示できる

#### 正常系

- show 相当 → レイヤ（またはホスト）が表示状態になる（`hidden` 解除または同等）
- hide 相当 → 非表示になる
- 既定で下部寄せのスタイル／構造がある（厳密ピクセルは必須としない。クラスまたは data 属性で識別できればよい）

#### 異常系

- 二重 show / 二重 hide → 例外を投げない

## TwUserMenu

### data-tw-component の付与

#### 正常系

- `<tw-user-menu>` を接続 -> `data-tw-component="user-menu"` がある
- 接頭辞を変えて登録しても `data-tw-component` は `"user-menu"` のまま

### Dropdown への合成（ActionMenu を使わない）

#### 正常系

- 接続後、ホスト配下に現接頭辞の Dropdown が存在する
- ホスト配下に ActionMenu ホストは**存在しない**
- `open()` / `close()` / `toggle()` および `open` 属性が内部 Dropdown と整合する

#### 異常系

- 既に開いている状態で `open()` -> 開いたまま（例外なし）

### trigger slot（必須）

#### 正常系

- `slot="trigger"` に Avatar＋テキスト等を置く -> その内容が trigger 領域に投影される
- trigger クリックでメニューが開く／閉じる（toggle）

#### 異常系

- trigger slot なし（または空）で接続 -> デフォルト trigger は作られない
- 同上のとき `console.warn` が少なくとも1回呼ばれる（Vitest で spy）
- 不明な `slot="foo"` は trigger／項目として扱わない（例外なし）

### メニュー項目（デフォルト slot）と自動クローズ

#### 正常系

- デフォルト slot に項目（例: `<a data-tw-user-menu-item>` やボタン）を置く -> 開いた panel 内に見える
- panel 内の項目をクリック -> メニューが閉じる

#### 異常系

- 項目が空の panel で開いても例外なし
- ホスト外クリック -> 閉じる（Dropdown 委譲）

### Escape / placement

#### 正常系

- 開いた状態で `Escape` -> 閉じる
- `placement="top-end"` -> 内部 Dropdown の placement がそれに追従（または同等）
- 未指定 -> 内部は `"bottom-start"`

#### 異常系

- 閉じた状態で `Escape` -> 何もしない（例外なし）
- 不正な `placement` -> `"bottom-start"` にフォールバック

### Avatar 属性をホストに持たない

#### 正常系

- ホストに `name` / `image-path` を付けても、組み込み Avatar は自動生成されない（trigger は利用側 slot のみ）

## TwCookieConsent

### data-tw-component の付与

#### 正常系

- `<tw-cookie-consent>` を接続 -> `data-tw-component="cookie-consent"` がある

### 初回接続（キー未作成）

テスト前に該当 localStorage キーを削除する。

#### 正常系

- 接続後、既定キー（`tw-cookie-consent`）に JSON が書かれる
- `status` は未承諾（`pending`）
- バナー（Snackbar レイヤ経由）が表示状態になる
- `expiresAt` が「今から ttl-days 日後」相当に設定される（許容誤差はテストで固定。例: ±数秒）

#### 異常系

- localStorage が使えない環境では例外を投げず、表示のみにフォールバックしてよい（実装で固定。不可ならスキップ理由をテストに書く）

### storage-key 属性

#### 正常系

- `storage-key="app-consent"` で接続 -> そのキーに読み書きする（既定キーは触らない）

#### 異常系

- 空の `storage-key` -> 既定キーにフォールバック（例外なし）

### ttl-days 属性

#### 正常系

- 未指定 -> TTL は 365 日相当
- `ttl-days="30"` -> 延長・初期 `expiresAt` が 30 日相当

#### 異常系

- 不正値（空・非数・0以下）-> 365 にフォールバック（例外なし）

### すべて承諾

#### 正常系

- 承諾アクション実行 -> `status === "accepted"`、`bannerHidden === true`
- バナーが非表示になる
- `service-ids="a,b"` があるとき -> `services` が `{ a: true, b: true }` になる
- `expiresAt` が「実行時点から ttl-days」に更新される

#### 異常系

- 既に accepted のあと再度承諾 -> 壊さず `bannerHidden` 維持（例外なし）

### 設定する（バナー非表示＋href）

#### 正常系

- 設定アクション実行（または同等メソッド）-> `status` は `pending` のまま、`bannerHidden === true`
- バナーが非表示になる
- 設定用リンクに `href` を渡せる（属性または slot 内 `<a>`。遷移の実ブラウザは必須としないが、href が保持されること）

#### 異常系

- `href` 未設定でもバナー非表示とストレージ更新はできる（例外なし）

### bannerHidden 再訪

#### 正常系

- `bannerHidden: true` の JSON を仕込んで接続 -> バナーは出ない
- `status: "accepted"` かつ期限内 -> バナーは出ない

### TTL スライディング

時計は Vitest の fake timers または `expiresAt` を直接操作して検証してよい。

#### 正常系

- 期限内の JSON がある状態で接続 -> `expiresAt` が「接続時点から ttl-days」へ延びる（以前より未来になる）
- バナー表示条件は `bannerHidden` / `status` に従う（延長だけで status を変えない）

#### 異常系

- 期限ちょうど／境界は実装で固定（例: `now >= expiresAt` を切れとする）し、テストに明記する

### TTL 切れ

#### 正常系

- `expiresAt` を過去にして接続 -> ストレージが削除される（またはキーが消える／初期 pending 相当にリセットされる）
- バナーが再表示される
- `status` は未承諾（`pending`）に戻る
- 以前の `services` は残らない（全リセット）

### サービス許否 API

#### 正常系

- `setServiceConsent("analytics", true)` -> `getServiceConsent("analytics") === true`、かつ `status === "partial"`
- 続けて `setServiceConsent("ads", false)` -> `status` は `"partial"` のまま
- すべて false にすると `status === "rejected"`
- `getAllServiceConsents()` に両方が含まれる
- ストレージ JSON の `services` に反映される
- 先に `acceptAll` したあと個別を true にすると `accepted` → `partial`

#### 異常系

- 未登録 id の `getServiceConsent` -> `undefined`
- 空文字 id は無視または no-op（例外なし。実装で固定）

### slot による文言

#### 正常系

- デフォルト slot（または named slot）に任意の説明・ボタンを置ける
- WC は組み込みの固定日本語コピーを必須としない（空でも接続できる）

#### 異常系

- slot 空でも接続・初回ストレージ初期化は動く（例外なし）

### Snackbar レイヤの利用

#### 正常系

- CookieConsent の表示／非表示が共有レイヤの show/hide を経由する（またはレイヤが一意に識別できる）
- Toast WC は登録・エクスポートされない（本版）

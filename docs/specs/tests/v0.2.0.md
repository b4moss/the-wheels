対象: 基盤 API（`setPrefix` / 自動登録 / `getEventName`）、`TwSvgLoader`、`TwSpinner`、`TwButton`。

## Core

### setPrefix(prefix: string) / getPrefix()

- グローバルな WC タグ接頭辞を設定・取得する
- デフォルトは `"tw-"`
- 末尾に `-` が無い場合は付与する（呼び出し側が `"app"` でも `"app-"` として扱う）

#### 正常系

- 初期状態で `getPrefix()` -> `"tw-"` が返る
- `setPrefix("app")` のあと `getPrefix()` -> `"app-"` が返る
- `setPrefix("app-")` のあと `getPrefix()` -> `"app-"` が返る（二重ハイフンにしない）

#### 異常系

- `setPrefix("")` -> デフォルト `"tw-"` にフォールバックする（空接頭辞は採用しない）
- `setPrefix("   ")` -> トリム後が空なら `"tw-"` にフォールバックする

### getEventName(name: string)

- 将来のカスタムイベント用に、接頭辞付きイベント名文字列を返す
- v0.2.0 では発火には使わない（純関数として検証する）

#### 正常系

- デフォルト接頭辞で `getEventName("open")` -> `"tw-open"` が返る
- `setPrefix("app")` 後に `getEventName("close")` -> `"app-close"` が返る
- `getEventName("modal-open")` -> `"tw-modal-open"` が返る（接頭辞は先頭に一度だけ付く）

#### 異常系

- `getEventName("")` -> `""` を返す（接頭辞だけの文字列にはしない）

### defineComponent(localName: string, ctor: CustomElementConstructor)

- `getPrefix() + localName` をタグ名として `customElements.define` する
- 既に同名が登録済みなら何もしない（例外を投げない）
- モジュール import 時の自動登録からも利用する

#### 正常系

- 接頭辞 `"tw-"`、`localName` `"button"` -> `customElements.get("tw-button")` が `ctor` と一致する
- `setPrefix("app")` 後に `localName` `"spinner"` を登録 -> `customElements.get("app-spinner")` が定義される
- 同じ `localName` / 接頭辞で二度呼ぶ -> 例外なく、登録は最初の `ctor` のまま

#### 異常系

- 既に別のコンストラクタで `"tw-button"` が登録されている状態で再呼び出し -> 何もしない（上書きしない・例外なし）

### 自動登録（モジュール import の副作用）

- 各コンポーネントモジュールを import すると、その時点の接頭辞でタグが登録される
- `setPrefix` は対象モジュールの import **より前**に呼ぶ前提

#### 正常系

- `setPrefix` なしで SVGLoader / Spinner / Button モジュールを import -> `tw-svg-loader` / `tw-spinner` / `tw-button` が定義される
- `setPrefix("app")` のあと各モジュールを import -> `app-svg-loader` / `app-spinner` / `app-button` が定義される

#### 異常系

- デフォルト接頭辞で一度登録したあと、同じテスト環境で `setPrefix("app")` しても、既登録の `tw-*` タグは付け替わらない（新規 `app-*` の再登録は別途モジュール再読込が必要なため、本版では「既存タグは維持」を確認する）

## TwSvgLoader

### data-tw-component の付与

- ホスト接続時に `data-tw-component="svg-loader"` を付与する（接頭辞変更後もこの値は固定）

#### 正常系

- `<tw-svg-loader>` を DOM に接続 -> `data-tw-component="svg-loader"` がある
- `app-svg-loader` として登録・接続した場合も `data-tw-component="svg-loader"` のまま

### SVG の fetch と描画

- `src` を `fetch` し、成功時は取得した SVG を Light DOM に描画する
- 独自のメモリキャッシュは持たない（同一 `src` でも都度 fetch してよい。HTTP キャッシュはブラウザ任せ）

#### 正常系

- 有効な SVG を返す URL を `src` に設定して接続 -> ホスト配下に `<svg>` が現れる
- `src` を別の有効 URL に変更 -> 新しい SVG 内容に更新される
- 同じ `src` を再設定しても例外なく描画をやり直せる（専用キャッシュ層がないことの確認）

#### 異常系

- `src` 未設定で接続 -> SVG もプレースホルダも出さない（空のまま）、例外は投げない
- `src=""` で接続 -> 同上（空のまま）
- fetch がネットワークエラー -> プレースホルダを描画する（破線枠または「?」相当。`<svg>` 本体の成功描画はしない）
- fetch が HTTP 404 / 500 -> プレースホルダを描画する
- レスポンス Body が SVG として解釈できない（例: `"not-svg"`） -> プレースホルダを描画する

### 見た目属性の反映

- `width` / `height` / `padding` / `stroke-width` / `fill-color` / `stroke-color` / `flip` / `rotate` をホストまたは注入 SVG に反映する

#### 正常系

- `width="24"` `height="24"` -> 描画結果の幅・高さが 24px 相当になる
- `padding="4"` -> 内側余白が付く
- `stroke-width="2"` -> ストローク幅が反映される
- `fill-color="#000000"` / `stroke-color="#494949"` -> 色が反映される
- `fill-color="var(--tw-text-main)"` -> CSS 変数値が受け入れられる（例外なし）
- `flip="horizontal"` / `"vertical"` / `"both"` -> 反転が適用される
- `rotate="90"` -> 90deg 回転が適用される

#### 異常系

- `flip="diagonal"`（未定義値） -> 反転を適用しない（例外なし）
- `rotate="abc"`（非数値） -> 回転を適用しない（例外なし）
- `width="-1"` など不正な数値 -> 当該寸法指定を無視する（例外なし）

## TwSpinner

### data-tw-component の付与

- ホスト接続時に `data-tw-component="spinner"` を付与する

#### 正常系

- `<tw-spinner>` を接続 -> `data-tw-component="spinner"` がある

### SVGLoader 経由の描画

- 内部で SVGLoader（現接頭辞のタグ）を使い描画する
- アニメーション用 CSS 回転は Spinner 自身では持たない（アセット側に任せる。スタイル自動テスト対象外）

#### 正常系

- `src` 省略で接続 -> 内部 SVGLoader の `src` が同梱 `spinner.svg` の URL になる
- `src` に任意 URL を指定 -> 内部 SVGLoader にその URL が渡る
- `width` / `height` 未指定 -> 内部サイズが `1em` 相当になる
- `width="32"` `height="32"` -> 内部 SVGLoader に同値が渡る
- `stroke-color` 等の見た目属性を付けた場合 -> 内部 SVGLoader に透過される

#### 異常系

- 同梱アセット URL の解決に失敗する環境でも、ホスト接続自体は例外を投げない（描画失敗時は SVGLoader のプレースホルダ経路に委ねる）

## TwButton

### data-tw-component の付与

- ホスト接続時に `data-tw-component="button"` を付与する

#### 正常系

- `<tw-button>` を接続 -> `data-tw-component="button"` がある

### 内部 button と type

- Light DOM 内にネイティブ `<button>` を持つ
- `type` 属性を内部 button に透過する（未指定時は `"button"`）

#### 正常系

- 属性なしで接続 -> 内部 `button[type="button"]` がある
- `type="submit"` -> 内部 button の type が `"submit"`
- `type="reset"` -> 内部 button の type が `"reset"`

#### 異常系

- `type=""` -> 内部 type は `"button"` にフォールバックする

### variant 属性の反映

- `variant` は `default` | `stroke` | `ghost`。未指定は `default`
- ホストまたは内部に識別できる印（属性・クラス等）を残し、スタイル側が参照できるようにする

#### 正常系

- 未指定 -> `default` として扱う
- `variant="stroke"` -> stroke として扱われる
- `variant="ghost"` -> ghost として扱われる
- `variant="default"` -> default として扱われる

#### 異常系

- `variant="primary"`（未定義値） -> `default` にフォールバックする

### slot 投影（icon-left / default / icon-right）

- Light DOM で `[slot="icon-left"]` / デフォルト内容 / `[slot="icon-right"]` を内部ラッパへ投影する
- 当該 slot に内容が無いときは、そのラッパ要素自体を描画しない

#### 正常系

- テキストのみ（デフォルト内容）-> ラベル領域にそのテキストがあり、左右アイコン用ラッパは無い
- `slot="icon-left"` 付き要素あり -> 左アイコン領域が存在し、その子として投影される
- `slot="icon-right"` 付き要素あり -> 右アイコン領域が存在し、その子として投影される
- 左右両方あり -> 両方の領域が存在する

#### 異常系

- `slot="icon-left"` が空（子なし・空白のみ等、内容なしとみなす場合）-> 左アイコン領域を描画しない
- 不明な `slot="foo"` のみ -> 左右アイコン領域は作らず、デフォルト内容の扱いに落とさない（無視またはデフォルト外として扱って例外なし）

### disable-on-click

- HTML 真偽属性。存在すれば有効
- 有効時、クリック後に内部 button を `disabled` にし、ラベルおよびアイコン slot を隠し、Spinner のみを表示する

#### 正常系

- `disable-on-click` ありでクリック -> 内部 button が disabled になる
- 同上 -> ラベル／アイコンが非表示（または DOM から除かれ）、Spinner（またはそのホスト）が現れる
- `disable-on-click` なしでクリック -> disabled にも Spinner にもならない

#### 異常系

- 既に `disabled` の状態でクリック -> 追加の状態遷移を起こさない（Spinner を二重に生やさない）
- `disable-on-click` を外しただけでは、クリック後に入った disabled / Spinner 状態は自動解除しない（`reset()` が必要）

### disabled 時の lock アイコン

- `disabled` 表示時、右上に同梱 `lock` を SVGLoader 経由で出す
- ラベル／スピナー表示とは別レイヤ

#### 正常系

- 初期から `disabled` 属性あり -> lock 用 SVGLoader（`lock` アセット）が現れる
- `disable-on-click` クリック後の disabled でも lock が現れる
- disabled 解除後（`reset()` または属性削除で有効化）-> lock が消える

#### 異常系

- disabled でない通常表示 -> lock を描画しない

### TwButton#reset()

- `disable-on-click` 後の disabled とスピナー状態を解除する
- 復帰用 UI は提供しない（メソッド呼び出しのみ）

#### 正常系

- `disable-on-click` クリック後に `reset()` -> 内部 button の disabled が解除される
- 同上 -> Spinner が消え、ラベル／アイコン表示が戻る
- 一度もクリックしていない状態で `reset()` -> 例外なく、表示は変わらない

#### 異常系

- 初期から `disabled` 属性だけが付いている要素で `reset()` -> `disable-on-click` 由来でない disabled は解除しない（属性としての `disabled` は利用側の管理）

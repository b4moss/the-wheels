# v0.11.0 テスト仕様

対象: `TwCombobox`、`TwInfiniteScroll`、および InfiniteScroll 向けマージ／ウィンドウ純関数。  
スタイル（CSS）の自動テストは行わない。カスタムイベントは原則発火しない（Combobox の `load-request` 第2経路のみ例外）。

関連仕様: [all.md](../components/all.md) / [combobox.md](../components/combobox.md) / [infinite_scroll.md](../components/infinite_scroll.md) / [dropdown.md](../components/dropdown.md)  
roadmap: [roadmap.md](../../roadmap.md)（v0.11.0）

計画上の補足（完了定義）:

- Combobox は内部に現接頭辞の Dropdown を持ち、開閉・配置・外側クリック／Escape を委譲する
- `mode` 未指定は `static`。`debounce` 既定 `300`（ms）。InfiniteScroll の `max-items` 既定 `100`、`sort-direction` 既定 `desc`
- Option は少なくとも `{ value, label }`。一意キーは `value`
- 値更新はホストプロパティと `change` イベント（バブリング可）。選択表示 UI はスロット（組み込みタグ UI なし）
- 出荷順の受け入れ: Combobox（`static` 単純リスト含む）→ InfiniteScroll → Combobox の `async` / `hybrid` は InfiniteScroll 経由でページング（実装上 `async` / `hybrid` は当初から InfiniteScroll を載せる）
- UserMenu / CookieConsent / a11y 本検討は本版の自動テスト対象外

## InfiniteScroll helpers（純関数）

実装名は問わない（例: `mergeWindowItems`）。Vitest で入出力を固定する。

### merge + sort

- 既存ウィンドウ配列と新規 `items` を `value` で重複排除して結合し、`sortKey` フィールドでソートする
- `sortDirection`: `"asc"` | `"desc"`（既定の呼び出し元は `desc`）

#### 正常系

- 空＋`[{ value: 1, label: "a", updated_at: 10 }]`（key=`updated_at`, desc）-> その1件
- 既存 `[t=20, t=10]` に `t=15` をマージ（desc）-> `[20, 15, 10]` の順
- 同一 `value` が新規側にある -> 新規側で上書き（または新規優先）。件数は増えない
- `asc` 指定時は昇順になる

#### 異常系

- `sortKey` が欠ける item は **末尾** に寄せ、例外を投げない
- `items` が空 -> 既存をソートし直した結果（または既存のまま）。例外なし

### trim window（max-items）

- ソート済み配列を最大 `maxItems` 件に切り詰める
- 下方向追記で溢れたときは **上端（ソート先頭側）から**落とす想定を基本とする（実装が逆の場合は仕様・本テストを合わせて更新）

#### 正常系

- `maxItems=3` で4件ある -> 3件になり、溢れた端が取り除かれる
- `maxItems` 以上ない -> 全件維持

#### 異常系

- `maxItems <= 0` -> **空配列**（例外なし）

## TwInfiniteScroll

### data-tw-component の付与

- ホスト接続時に `data-tw-component="infinite-scroll"` を付与する（接頭辞変更後も固定）

#### 正常系

- `<tw-infinite-scroll>` を接続 -> `data-tw-component="infinite-scroll"` がある
- 接頭辞を変えて登録しても `data-tw-component` は `"infinite-scroll"` のまま

### 初期ロード

- 接続後、`autoLoad` が true（既定）ならローダを `direction: "initial"` で呼ぶ
- `autoLoad` が false なら接続だけでは呼ばず、親が `refresh()` 等で明示する（Combobox は二重 fetch 防止のため false をセット）
- 戻り `{ items, hasMore, nextPage? }` をマージ／ソートして表示する

#### 正常系

- ローダが `{ items: [...], hasMore: true }` を返す -> リストに items が `sort-key` 順で並ぶ
- `hasMore: false` -> 当該方向の追加ロードを行わない
- `autoLoad=false` で接続 -> 自動の `initial` 呼び出しをしない

#### 異常系

- ローダ未設定で接続 -> 例外を投げない（空リスト）
- ローダが reject -> 例外をホスト外へ投げず、リストは前回状態または空を維持（実装で固定）

### 下端・上端ロード

- スクロールが下端付近で `direction: "down"`、上端付近で `direction: "up"` のローダ呼び出し
- 結果をマージ／ソートし、`max-items` 超ならウィンドウを切り詰める

#### 正常系

- 下端到達かつ `hasMore`（下）が true -> ローダが `down` で呼ばれ、件数が増える（またはウィンドウ内で入れ替わる）
- 上端到達かつ `hasMore`（上）が true -> `up` で呼ばれる
- 切り詰め後、破棄した方向へ再度端到達 -> 再 fetch される

#### 異常系

- `hasMore` が false の方向では端到達してもローダを呼ばない
- ロード中の再入は無視またはキュー（二重で壊さない。例外なし）

### sort-key / sort-direction / max-items 属性

#### 正常系

- `sort-key="updated_at"` / `sort-direction="asc"` がマージ結果の順に反映される
- 未指定の `sort-direction` -> `"desc"`
- 未指定の `max-items` -> `100`
- `max-items="5"` -> 保持件数が最大5

#### 異常系

- 不正な `sort-direction` -> `"desc"` にフォールバック
- 不正な `max-items` -> 既定 `100` またはフォールバック値（例外なし）

### クエリ／リセット

- 親からクエリ変更相当の API（例: `reset({ query })` またはプロパティ）でウィンドウを捨て、`initial` から取り直す

#### 正常系

- リセット後、ローダが新しい `query` で `initial` 呼び出しされる
- 以前の items はリストから消える

#### 異常系

- ロード中にリセット -> 進行中の取得は Abort または結果破棄（古い結果で上書きしない）

### スクロール位置（がたつき抑制）

- マージ再描画後、ユーザーが注視していた付近が大きく飛ばないこと

#### 正常系

- 下方向追加後、既存先頭付近の要素がまだウィンドウ内なら、その要素の可視位置がおおよそ維持される（厳密ピクセル一致は必須としない。アンカー前後のオフセット差が許容内、または同等のアサーション）

#### 異常系

- ウィンドウからアンカーが消えた場合はベストエフォート（例外なし）

## TwCombobox

### data-tw-component の付与

#### 正常系

- `<tw-combobox>` を接続 -> `data-tw-component="combobox"` がある
- 接頭辞変更後も `data-tw-component="combobox"`

### Dropdown への合成

#### 正常系

- 接続後、ホスト配下に現接頭辞の Dropdown が存在する
- `open()` / `close()` / `toggle()` および `open` 属性が内部 Dropdown と整合する
- trigger クリックで開閉、外側クリック／Escape で閉じる（Dropdown 委譲）

#### 異常系

- 既に開いている状態で `open()` -> 開いたまま（例外なし）

### パネル構成と slot

- パネル内の上から: 検索フィールド → `subarea` → リスト → `footer`
- `trigger` スロットで発動領域の中身を渡す（選択表示は利用側）
- オプション行の差し替えはスロットではなく JS プロパティ `renderOption`（下記）

#### 正常系

- `slot="trigger"` の内容が trigger 領域に投影される
- `slot="subarea"` が検索とリストのあいだに出る
- `slot="footer"` がリストの下に出る
- slot なしでも接続・開閉でき、例外なし（trigger 空でも可）

#### 異常系

- 不明な `slot="foo"` は上記領域の投影対象にしない（例外なし）

### mode 属性

#### 正常系

- 未指定 -> `"static"` として扱う
- `mode="static"` / `"async"` / `"hybrid"` がそれぞれ受け入れられる

#### 異常系

- 不正値（例: `mode="nope"`）-> `"static"` にフォールバック

### static: options とクライアント検索

#### 正常系

- `options = [{ value: 1, label: "Apple" }, { value: 2, label: "Banana" }]` で開く -> 両方の label が見える
- 検索に `"app"`（大文字小文字は実装方針で固定。既定は **大文字小文字無視の部分一致**）-> Apple のみ（または一致分のみ）
- 検索を空に戻す -> 全件（フィルタ前）に戻る

#### 異常系

- `options` 未設定 -> 空リスト（例外なし）
- 一致なし -> 空状態を示す（空メッセージの有無は任意。例外なし）

### async: loadOptions と debounce

#### 正常系

- `loadOptions` を設定し検索入力 -> 既定 300ms 後にローダが呼ばれる（テストは `debounce="0"` またはタイマーモックでよい）
- 呼び出し `ctx` に `query` / `page` / `signal` がある
- 戻り `{ items, hasMore }` の items がリストに反映される
- 連続入力で前回の `signal` が abort される（または古い結果が採用されない）

#### 異常系

- `loadOptions` なしの `async` -> 第2経路へ、または空のまま（例外なし）。第2経路は下記
- ローダ reject -> リストを壊さず、loading を解除する

### debounce 属性

#### 正常系

- 未指定 -> 300ms
- `debounce="0"` -> 実質即時（テスト容易）
- `debounce="50"` -> その間隔

#### 異常系

- 不正値 -> 300 にフォールバック（例外なし）

### hybrid

#### 正常系

- 静的 `options` が初期リストに出る
- 検索（または初期 async 負荷）で `loadOptions` 結果が乗り、sortKey マージ規則に従う
- `async` / `hybrid` は当初から InfiniteScroll をリスト領域に載せる（単純リスト段階を経ない）

#### 異常系

- `options` のみで `loadOptions` なし -> 静的側だけ動く（例外なし）

### 第2経路: load-request + applyLoadResult

- `loadOptions` 未設定時、取得が必要なら `getEventName("load-request")` 名のカスタムイベントを発火する
- 利用側は `applyLoadResult({ items, hasMore, nextPage? })` で結果を返す

#### 正常系

- リスナが event.detail（または同等）から query 等を読み、`applyLoadResult` するとリストに反映される
- `loadOptions` があるときは第2経路を使わない（イベント非発火）

#### 異常系

- イベント後に `applyLoadResult` されない -> **次の microtask** で loading を解除し、空結果（`{ items: [], hasMore: false }` 相当）とする（例外なし）

### 選択（単一）

#### 正常系

- オプション行クリック -> `value` がその option の value になる
- `change` が発火する（target はホスト）
- 同じ値を再選択しても壊らない（閉じる／維持は実装で固定）

#### 異常系

- `disabled: true` の option は選択できない
- `disabled` 属性（ホスト）中は開閉・選択できない

### 選択（複数）

#### 正常系

- `multiple` で複数 value を配列として保持できる
- 選択済みの再クリックで解除できる（トグル）
- `max-selected="2"` のとき3件目は追加されない（または追加前に拒否）

#### 異常系

- `max-selected` 不正値 -> 上限なし、または無視（例外なし）

### デフォルト行と renderOption

#### 正常系

- `renderOption` 未設定 -> 各行に `label` テキストが出る
- JS プロパティ `renderOption(option, selected)` でカスタム行（`HTMLElement` 等）を出せる（スロット／テンプレートではない）

#### 異常系

- `label` 欠落 -> 空文字または value の文字列化（例外なし）

### placeholder / placement

#### 正常系

- `placeholder` は検索入力の placeholder に反映する
- `placement` は内部 Dropdown に透過する（未指定は `bottom-start`）

#### 異常系

- 不正 `placement` -> Dropdown と同様 `bottom-start`

### loading 表示

#### 正常系

- async 取得中、リスト領域に loading 状態が分かる（テキストまたは属性／クラス）

#### 異常系

- 取得完了後は loading が消える

## TwCombobox × TwInfiniteScroll 接続

### static では InfiniteScroll を使わない

#### 正常系

- `mode="static"` で開いても、リスト領域に InfiniteScroll ホストを必須としない（単純リスト）

### async / hybrid でページング委譲

#### 正常系

- `mode="async"` / `"hybrid"` ではリスト領域に InfiniteScroll を当初から載せる（単純リスト段階なし）
- Combobox は内側 InfiniteScroll の `autoLoad` を false にし、自前のオーケストレーションで `refresh` 相当を行う（二重 fetch 防止）
- 検索クエリ変更で InfiniteScroll がリセットされ、新しい query で `initial` 相当が走る
- 下端スクロールで追加ページが載る（ローダが `down` で呼ばれる）

#### 異常系

- `hasMore: false` 後は追加呼び出ししない

### hybrid のマージ

#### 正常系

- 初期静的 options と fetch 結果が `sort-key` で一つの順序になる（重複 value は1つ）

## 対象外（この版の自動テストに含めない）

- CSS / 見た目（影、hover、ピクセル単位の厳密一致）
- a11y（フォーカストラップ、ARIA、キーボード一覧ナビの本検討）
- 組み込みカテゴリ AND/OR、タグ UI、ColorTip / Avatar 行
- 比較関数 `compare(a, b)`、全件保持の仮想スクロール
- UserMenu / CookieConsent
- Storybook / Playwright E2E（表示確認は手動または後続版）
- npm 公開

# v0.10.0 テスト仕様

対象: Git / GitHub 戦略（[git.md](../../git.md)）に沿った **PR CI** をモノレポに入れること。  
成果物の中心は GitHub Actions ワークフローと、方針ドキュメントとの整合である。アプリの新機能ロジックは追加しない。

Vitest の新規ユニット／結合ケース追加は必須としない（既存 `test:components` / `test:package` を CI から実行する）。スタイル VRT・Playwright E2E・a11y 本実装・npm publish は行わない。

関連: [roadmap.md](../../roadmap.md) v0.10.0 / [git.md](../../git.md) / [test.md](../../test.md)

計画上の補足（完了定義）:

- PR 先が `develop` または `dev-v*` のときに CI が走る
- ジョブ内で `npm ci` → `build:style` → `test:components` → `test:package` → `build:kitchen-sink` → `build:storybook` が順に成功すること
- Node.js 22 / `contents: read` / concurrency / npm cache
- `main` / `release` 向け CI・release dry-run / CD は **この版の必須外**
- バージョンタグ `v0.10.0` は **この版ブランチ tip には付けない**（`main` マージ後ルール）
- workspace の version を **0.10.0** に揃える

---

## ワークフローファイル

### `.github/workflows/ci.yml` の存在と基本設定

- GitHub Actions 用の CI 定義をリポジトリに置く
- 権限は最小（読み取り中心）
- 同一 PR の重複実行を抑える

#### 正常系

- パス `.github/workflows/ci.yml` が存在する
- `permissions.contents` が `read`（それ以外の広い write 権限をこの版で必須にしない）
- `concurrency` が定義され、同一グループ内で新しい実行が古いものをキャンセルする（例: `cancel-in-progress: true`）
- ジョブは `ubuntu-latest`（または同等の Linux runner）で動く

#### 異常系

- ワークフローが無く、PR で自動検証が走らない状態は不合格
- `contents: write` など、この版の CI に不要な広い権限だけを持つ定義は不合格（意図した最小権限でない）

---

## トリガー

### `develop` / `dev-v*` への pull_request

- git.md の「CI が走るタイミング」に合わせる
- `main` / `release` では走らせない

#### 正常系

- `on.pull_request.branches` に `develop` が含まれる
- `on.pull_request.branches` に `dev-v*` パターン（または同等の glob）が含まれる
- `push` のみ・`workflow_dispatch` のみ、など PR をカバーしない定義だけ、にはしない（PR 時実行が必須）

#### 異常系

- `main` や `release` を CI トリガー対象に含めている状態は不合格（この版の方針）
- `develop` / `dev-v*` のどちらもカバーしていない状態は不合格

---

## セットアップ手順

### Node 22・npm ci・キャッシュ

- engines（`node >=22`）に合わせたランタイムで依存を固定インストールする

#### 正常系

- `actions/setup-node`（または同等）で **Node.js 22** を使う
- npm のキャッシュが有効（`cache: npm` 等）
- 依存インストールは `npm ci`（lockfile 前提。`npm install` のみの本番 CI は不合格）

#### 異常系

- Node 18 / 20 固定など、engines と明らかに食い違うバージョン固定は不合格
- lockfile を無視して毎回解決し直すだけのインストールは不合格

---

## 検証ステップ（ジョブ内コマンド）

### テストと主要ビルドの連続実行

- モノレポの回帰として、スタイル・コンポーネントテスト・パッケージスモーク・アプリ静的ビルドを CI で担保する
- ルートの npm scripts を使う（workspace 直叩きに寄せすぎない）

#### 正常系

- 次を **この順**（または同等の依存順で、後続が前段成果物を必要とする関係を崩さない順）で実行するステップがある
  1. `npm run build:style`
  2. `npm run test:components`
  3. `npm run test:package`
  4. `npm run build:kitchen-sink`
  5. `npm run build:storybook`
- いずれも非ゼロ終了でジョブ全体が失敗する（失敗を握りつぶさない）

#### 異常系

- `test:components` または `test:package` が無い状態は不合格
- kitchen-sink / Storybook の build がどちらも無い状態は不合格
- `build:style` が無く、スタイル成果物前提の後続だけがある状態は不合格

## ドキュメント整合

### git.md / README

- ワークフローの所在と、マージ不可運用の土台（ブランチ保護）を文書化する
- ブランチ保護の実設定は GitHub UI 上の **【PO作業】**

#### 正常系

- [git.md](../../git.md) にワークフローパス（`.github/workflows/ci.yml`）が書かれている
- git.md に、`develop` / `dev-v*` 向け PR で required status check を求める **【PO作業】** チェックリスト（または同等の手順メモ）がある
- README に CI（または git.md への案内）への短い言及がある
- タグ方針として、バージョンタグは `main` マージ後に付くこと／`dev-v*` tip に付けないことが git.md と矛盾しない

#### 異常系

- CI ファイルはあるがドキュメントから辿れず、ブランチ保護が PO 作業であることも書かれていない状態は不合格（この版の合格条件）

## バージョン表記

### 0.10.0

- 本マイルストーンに合わせ、公開／開発用 workspace の version を 0.10.0 に揃える

#### 正常系

- root および `packages/*` / `apps/*` の `package.json` の `version` が `0.10.0`
- workspace 間の内部依存バージョン（例: `@b4moss/the-wheels-components`）も `0.10.0` に揃う
- `package-lock.json` が上記と整合する

#### 異常系

- CI だけ入れて package version が 0.9.0 のまま大きく食い違う状態は不合格

## 対象外（この版の自動テスト・合格条件に含めない）

- `main` への CI
- `release` 向け dry-run ワークフロー
- `release` マージ後の npm CD / publish
- バージョンタグ `v0.10.0` を `dev-v0.10.0` tip に付けること（**禁止**。`main` マージ後ルール）
- 新規 WC・kitchen-sink 機能・Storybook 機能追加
- VRT / Playwright / a11y 本実装
- GitHub 上のブランチ保護ルールの実適用そのもの（文書化と 【PO作業】 まで。設定操作は PO）

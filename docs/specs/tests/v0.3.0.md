# v0.3.0 テスト仕様

対象: `TwDropdown`、`TwActionMenu`、および Floating UI 向けの placement 正規化など付随ロジック。  
スタイル（CSS）の自動テストは行わない。カスタムイベントは発火しない。

関連仕様: [all.md](../components/all.md) / [dropdown.md](../components/dropdown.md) / [action_menu.md](../components/action_menu.md) / [icons.md](../icons.md)

計画上の補足（仕様書が短い箇所の完了定義）:

- 開閉 API: `open` 真偽属性 + `open()` / `close()` / `toggle()`
- 閉じる条件: 外側クリック、trigger 再クリック（toggle）、`Escape`。ActionMenu は panel 内クリックでも閉じる
- panel は portal しない。Floating UI は `offset(8)` / `flip` / `shift({ padding: 8 })`、不正 `placement` は `bottom-start`
- ActionMenu は内部に Dropdown を生成して委譲。デフォルト trigger は素の `<button>` + SVGLoader（`more-vertical.svg`）

## Floating helpers

### normalizePlacement(value: string | null | undefined)

- Floating UI に渡す `placement` を正規化する
- 未指定・空は `"bottom-start"`
- 不正値は `"bottom-start"` にフォールバックする
- 正当値はそのまま返す（少なくとも Floating UI が受け入れる主要 placement）

#### 正常系

- `normalizePlacement(undefined)` / `null` / `""` -> `"bottom-start"`
- `normalizePlacement("bottom-start")` -> `"bottom-start"`
- `normalizePlacement("top-end")` -> `"top-end"`
- `normalizePlacement("right")` -> `"right"`

#### 異常系

- `normalizePlacement("diagonal")` -> `"bottom-start"`
- `normalizePlacement("   ")` -> `"bottom-start"`

## TwDropdown

### data-tw-component の付与

- ホスト接続時に `data-tw-component="dropdown"` を付与する（接頭辞変更後も固定）

#### 正常系

- `<tw-dropdown>` を接続 -> `data-tw-component="dropdown"` がある
- `app-dropdown` として登録・接続しても `data-tw-component="dropdown"` のまま

### slot 投影（trigger / panel）

- Light DOM で `[slot="trigger"]` / `[slot="panel"]` を内部ラッパ（`.trigger` / `.panel` 等）へ投影する

#### 正常系

- `slot="trigger"` と `slot="panel"` の両方あり -> それぞれの領域に内容が投影される
- trigger / panel の内容を後から変更（再投影）しても例外なく反映できる

#### 異常系

- slot なしで接続 -> 例外を投げない（空の構造でよい）
- 不明な `slot="foo"` のみ -> trigger/panel としての投影対象にはしない（例外なし）

### open / close / toggle と open 属性

- `open()` で開く、`close()` で閉じる、`toggle()` で反転する
- 開閉状態は `open` 真偽属性に反映する（存在すれば開いている）
- 閉じているとき panel は非表示（`hidden` または同等）。開いているとき非表示を解除する

#### 正常系

- 初期状態は閉じている（`open` 属性なし、panel 非表示）
- `open()` -> `open` 属性が付き、panel が表示される
- `close()` -> `open` 属性が外れ、panel が非表示になる
- 閉じた状態で `toggle()` -> 開く
- 開いた状態で `toggle()` -> 閉じる
- HTML で最初から `open` を付けて接続 -> 開いた状態で始まる

#### 異常系

- 既に開いている状態で `open()` -> 開いたまま（例外なし、二重に壊れない）
- 既に閉じている状態で `close()` -> 閉じたまま（例外なし）

### trigger クリック

- trigger 領域のクリックで `toggle()` 相当の開閉をする

#### 正常系

- 閉じた状態で trigger をクリック -> 開く
- 開いた状態で trigger をクリック -> 閉じる

#### 異常系

- panel 内のクリックだけでは（Dropdown 単体では）閉じない（ActionMenu 側の責務）

### 外側クリックで閉じる

- 開いている間のみ document 等で外側クリックを監視する
- ホスト要素の外側のクリックで閉じる。ホスト内（trigger / panel）は外側とみなさない

#### 正常系

- 開いた状態でホスト外をクリック -> 閉じる
- 開いた状態で trigger をクリック -> toggle により閉じる（外側クリックと矛盾しない）
- 開いた状態で panel 内をクリック -> 開いたまま（Dropdown 単体）

#### 異常系

- 閉じている間は外側クリックで状態が変わらない（リスナ未登録または no-op）

### Escape で閉じる

- 開いているときに `Escape` キーで閉じる

#### 正常系

- 開いた状態で `Escape` -> 閉じる

#### 異常系

- 閉じた状態で `Escape` -> 何もしない（例外なし）

### placement 属性

- `placement` 属性で Floating UI の placement を変更する（デフォルト `bottom-start`）
- 不正値は `bottom-start` にフォールバック
- 変更時は開いていれば再計算する（例外なく完了する）

#### 正常系

- 未指定 -> 内部 placement は `"bottom-start"`
- `placement="top-end"` -> 内部 placement は `"top-end"`
- 開いた状態で `placement` を変更 -> 例外なく再配置処理が走る

#### 異常系

- `placement="nope"` -> `"bottom-start"` として扱う

### Floating UI 連携（振る舞いレベル）

- 開いている間だけ位置更新（`autoUpdate` 相当）を行う
- 閉じたら更新を止める
- flip / shift は有効（middleware 組み立て単位で検証してよい。ピクセル座標の厳密断言は必須としない）

#### 正常系

- `open()` 後 -> panel が表示され、配置処理が少なくとも一度は実行される（または panel に位置スタイル／座標が設定される）
- `close()` 後 -> 継続的な位置更新が止まる（二重呼び出しや切断で例外なし）

#### 異常系

- trigger または panel が空のまま `open()` -> 例外を投げない（配置をスキップしてよい）

## TwActionMenu

### data-tw-component の付与

- ホスト接続時に `data-tw-component="action-menu"` を付与する

#### 正常系

- `<tw-action-menu>` を接続 -> `data-tw-component="action-menu"` がある

### Dropdown への合成

- 内部に現接頭辞の Dropdown（例: `tw-dropdown`）を持ち、開閉・配置を委譲する

#### 正常系

- 接続後、ホスト配下に Dropdown ホストが存在する
- `open()` / `close()` / `toggle()` を ActionMenu で呼ぶと、内部 Dropdown の開閉状態がそれに追従する
- ActionMenu の `open` 属性も内部状態と整合する（委譲先と矛盾しない）

#### 異常系

- Dropdown モジュール未登録の環境では接続時に分かりやすく失敗するか、登録済み前提でテストする（本リポジトリでは index 経由の自動登録を前提とする）

### デフォルト trigger アイコン

- デフォルトは同梱 `more-vertical.svg` を SVGLoader で表示する
- 素の `<button type="button">` を trigger とする（`TwButton` 必須ではない）

#### 正常系

- `src` 未指定で接続 -> 内部 SVGLoader の `src` が同梱 `more-vertical` の URL（定数）と一致する
- デフォルト trigger ボタンが存在する

#### 異常系

- アセット URL が data URL 化されても、定数照合で一致すればよい（ファイル名文字列を含むことまでは必須としない）

### src によるアイコン差し替え

- `src` 属性があるとき、デフォルト trigger 内 SVGLoader にその URL を渡す

#### 正常系

- `src="https://example.com/icon.svg"` -> 内部 SVGLoader の `src` がその値になる
- `src` を後から変更 -> 内部 SVGLoader に反映される

#### 異常系

- `src=""` -> 同梱デフォルト URL にフォールバックする（または空を渡さずデフォルトを維持。例外なし）

### slot="trigger" による trigger 差し替え

- 利用側が `slot="trigger"` を渡した場合、デフォルト trigger（ボタン＋アイコン）の代わりにそれを使う

#### 正常系

- カスタム trigger を渡す -> デフォルトの more-vertical ボタンは使わず、渡した内容が trigger になる
- カスタム trigger クリックでメニューが開く

#### 異常系

- `slot="trigger"` と `src` が両方ある場合 -> trigger slot が優先され、デフォルトアイコン経路は使わない（`src` は無視してよい）

### メニュー項目（デフォルト slot）と自動クローズ

- デフォルト slot の内容を Dropdown の panel へ投影する
- panel 内の任意クリック（バブリング）でメニューを閉じる（`role=menuitem` 必須にしない）

#### 正常系

- 項目（例: ボタンやリンク）をデフォルト slot に置いて開く -> panel 内にその項目が見える
- panel 内の項目をクリック -> メニューが閉じる

#### 異常系

- panel 外（ホスト外）クリック -> Dropdown の外側クリックにより閉じる
- 項目が無い空の panel で開いても例外なし

### placement の透過

- ActionMenu の `placement` を内部 Dropdown に透過する

#### 正常系

- `placement="top-start"` -> 内部 Dropdown の placement が `"top-start"`（または同等）になる
- 未指定 -> 内部はデフォルト `"bottom-start"`

#### 異常系

- 不正な `placement` -> 内部は `"bottom-start"` にフォールバック

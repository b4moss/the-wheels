# v0.4.0 テスト仕様

対象: `TwAccordion`、グループ一斉開閉、`TwModal`。  
スタイル（CSS）の自動テストは行わない。カスタムイベントは発火しない（`<dialog>` の標準イベントは利用してよい）。

関連仕様: [all.md](../components/all.md) / [accordion.md](../components/accordion.md) / [modal.md](../components/modal.md) / [icons.md](../icons.md)

計画上の補足（仕様書が短い箇所の完了定義）:

- Accordion: 内部は `<details>` / `<summary>`。ホストに `open()` / `close()` と `open` 真偽属性を持ち、内部 `details.open` と双方向同期
- グループ一斉開閉: document クリック委譲を1回だけ登録。`data-tw-accordion-open` / `data-tw-accordion-close` → 同値の `data-tw-accordion-group` を持つ accordion を全開/全閉
- chevron: 同梱 `chevron.svg`。閉じ `rotate="0"`、開き `rotate="180"`
- Modal: 自律 CE + 内部 `<dialog>`。`showModal()` / `close()` を委譲。opener slot は持たない
- Modal 閉じる: ×（`data-tw-modal-close` + `close.svg`）、任意の `data-tw-modal-close`、backdrop（`event.target === dialog`）、Escape（標準）
- Modal サイズ: 初回 `showModal()` 後に幅・高さを inline 固定。再 open では維持。内容増減は content 内スクロール

## Accordion group helpers

### openAccordionsByGroup(groupId: string) / closeAccordionsByGroup(groupId: string)

- ドキュメント内の `[data-tw-component="accordion"][data-tw-accordion-group="<groupId>"]` を一括で開く / 閉じる
- 該当ホストがいなければ何もしない（例外なし）

#### 正常系

- 同一 `groupId` の Accordion が複数あるとき `openAccordionsByGroup` -> すべて開く（`open` 属性または内部 `details.open` が true）
- 同上で `closeAccordionsByGroup` -> すべて閉じる
- 飛地（DOM 上離れた位置）の同一グループも対象になる

#### 異常系

- 存在しない `groupId` -> 何もしない（例外なし）
- `groupId` が空文字 -> 何もしない（例外なし）

### ensureAccordionGroupDelegation()

- document にクリック委譲を登録する（多重呼び出しでもリスナは実質1回）
- `[data-tw-accordion-open="id"]` クリック -> `openAccordionsByGroup("id")`
- `[data-tw-accordion-close="id"]` クリック -> `closeAccordionsByGroup("id")`

#### 正常系

- 委譲登録後、open 用ボタンをクリック -> 対応グループがすべて開く
- 委譲登録後、close 用ボタンをクリック -> 対応グループがすべて閉じる
- `ensureAccordionGroupDelegation()` を二度呼んでも、開閉が二重に壊れない（例外なし・期待どおり1回分の動作）

#### 異常系

- open/close 属性を持たない要素のクリック -> Accordion 状態は変わらない
- 属性値に一致するグループが無いボタンをクリック -> 何もしない（例外なし）

## TwAccordion

### data-tw-component の付与

- ホスト接続時に `data-tw-component="accordion"` を付与する（接頭辞変更後も固定）

#### 正常系

- `<tw-accordion>` を接続 -> `data-tw-component="accordion"` がある
- `app-accordion` として登録・接続しても `data-tw-component="accordion"` のまま

### 内部構造（details / summary）

- 1ホスト = 1パネル。内部に `<details>` を1つ描画する
- `summary` に header、本体に content を載せる

#### 正常系

- 接続後、ホスト配下に `details` がちょうど1つある
- `details` 内に `summary` がある

#### 異常系

- slot が空でも接続時に例外を投げない（空の details/summary 構造でよい）

### slot 投影（header / content）

- Light DOM で `[slot="header"]` / `[slot="content"]` を内部へ投影する
- デフォルト slot は使わない

#### 正常系

- `slot="header"` の内容が `summary` 内に現れる（chevron と共存してよい）
- `slot="content"` の内容が `details` 本体側に現れる

#### 異常系

- 不明な `slot="foo"` のみ -> header/content としては投影しない（例外なし）
- デフォルト slot 相当の素の子テキストだけがある場合 -> header/content 専用投影の対象にしない（例外なし）

### open / close と open 属性（details 同期）

- `open()` で開く、`close()` で閉じる
- `open` 真偽属性と内部 `details.open` を双方向同期する
- ネイティブの summary クリックによる開閉も、ホストの `open` 属性と矛盾しない

#### 正常系

- 初期状態は閉じている（`open` なし、`details.open === false`）
- `open()` -> ホストに `open` が付き、`details.open === true`
- `close()` -> `open` が外れ、`details.open === false`
- HTML で最初から `open` を付けて接続 -> 開いた状態で始まる
- 開いた状態で summary をクリック（または `details` の `toggle`）-> 閉じ、ホストの `open` も外れる
- 閉じた状態で summary をクリック -> 開き、ホストに `open` が付く

#### 異常系

- 既に開いている状態で `open()` -> 開いたまま（例外なし）
- 既に閉じている状態で `close()` -> 閉じたまま（例外なし）

### chevron インジケータ

- summary 内に SVGLoader で同梱 `chevron.svg` を表示する
- 閉じ: `rotate="0"`、開き: `rotate="180"`

#### 正常系

- 接続直後（閉じ）-> chevron 相当の SVGLoader があり、`rotate` が `0`（または未設定と同等の 0）
- `open()` 後 -> 当該 SVGLoader の `rotate` が `"180"`
- `close()` 後 -> `"0"` に戻る

#### 異常系

- アセット URL が data URL 化されても、定数照合で chevron ソースと一致すればよい

### data-tw-accordion-group と一斉開閉連携

- ホストの `data-tw-accordion-group` でグループに参加する
- Accordion モジュールの import / 接続によりグループ委譲が有効になる

#### 正常系

- 同一グループの複数 Accordion + open ボタン -> すべて開く
- 同一グループの複数 Accordion + close ボタン -> すべて閉じる
- 別グループの Accordion は影響を受けない

#### 異常系

- `data-tw-accordion-group` 未設定の Accordion は一斉開閉の対象にならない

### 複数パネル同時オープン

- ネイティブ `details` のまま、複数ホストを同時に開けてよい（排他制御なし）

#### 正常系

- グループなしの Accordion A/B をそれぞれ `open()` -> 両方とも開いたまま

## TwModal

### data-tw-component の付与

- ホスト接続時に `data-tw-component="modal"` を付与する

#### 正常系

- `<tw-modal>` を接続 -> `data-tw-component="modal"` がある

### 内部 dialog（自律 CE）

- ホスト内部にネイティブ `<dialog>` を1つ描画する
- `HTMLDialogElement` の継承（customized built-in）は使わない

#### 正常系

- 接続後、ホスト配下に `dialog` がちょうど1つある
- ホスト自身は `HTMLElement` のカスタム要素である（`HTMLDialogElement` ではない）

### slot 投影（header / content / footer）

- `[slot="header"]` / `[slot="content"]` / `[slot="footer"]` を内部領域へ投影する
- デフォルト slot は使わない
- opener / initiater 用 slot は持たない

#### 正常系

- 各 slot の内容が対応領域に現れる
- content のみでも接続できる（header/footer 空）

#### 異常系

- 該当 slot が空のとき、その領域ラッパは描画しない（ただしデフォルト × 用の header 領域は下記のとおり例外）
- 不明な `slot="foo"` -> 投影しない（例外なし）

### デフォルト閉じるボタン（×）

- header 右上相当に閉じるボタンをデフォルトで置く
- 同梱 `close.svg` を SVGLoader で描画し、要素に `data-tw-modal-close` を付ける
- `header` slot が空でも × は出す（閉じる手段を欠かないため）

#### 正常系

- 接続後、`data-tw-modal-close` を持つデフォルトボタン（またはそのホスト）が存在する
- 内部 SVGLoader の `src` が同梱 close の URL（定数）と一致する

#### 異常系

- 利用側が別に `data-tw-modal-close` を置いても、デフォルト × は残ってよい（複数 closer 可）

### TwModal#showModal() / TwModal#close()

- `showModal()` は内部 dialog の `showModal()` に委譲する（`show()` は公開しない）
- `close()` は内部 dialog の `close()` に委譲する

#### 正常系

- `showModal()` -> 内部 dialog が開く（`open` または `open` 相当の状態）
- 開いた状態で `close()` -> 内部 dialog が閉じる
- 利用側ボタンから `element.showModal()` を呼べば開く（opener slot 不要）

#### 異常系

- 既に開いている状態で `showModal()` -> 例外なく開いたまま（または dialog 標準の挙動）
- 既に閉じている状態で `close()` -> 例外なく閉じたまま
- ホストに `show()` メソッドを公開しない（存在しない、または呼んでも dialog.show 相当を使わない）

### 閉じる経路

- デフォルト × クリックで閉じる
- ホスト内の任意の `[data-tw-modal-close]` クリックで閉じる（動的追加にも追従する）
- backdrop: dialog 自身へのクリック（`event.target === dialog`）で閉じる
- Escape: dialog 標準の閉じる挙動に任せる（可能な環境では閉じることを確認）

#### 正常系

- 開いた状態でデフォルト × をクリック -> 閉じる
- footer 等に置いた `[data-tw-modal-close]` をクリック -> 閉じる
- 開いたあと動的に追加した `[data-tw-modal-close]` をクリック -> 閉じる
- dialog 要素自体をクリック（backdrop 相当）-> 閉じる
- 開いた状態で Escape -> 閉じる（happy-dom 等で dialog の Escape が未実装なら、当該環境ではスキップ可とし、実装はネイティブ委譲であることをコードレビュー相当で担保）

#### 異常系

- content 内の通常クリック（`data-tw-modal-close` なし、target が dialog 自身でない）-> 閉じない
- 閉じている間の closer クリック -> 例外なし（閉じたまま）

### サイズ固定（初回 showModal 後）

- 初回 `showModal()` 後のレイアウト確定時に、dialog の幅・高さを inline スタイルで固定する
- 以降の内容増減は content 領域のスクロールで吸収する（dialog 外形の再計測・再固定はしない）
- 再 `showModal()` でも、一度固定した値を維持する

#### 正常系

- 初回 `showModal()` 後 -> dialog に width / height（または同等）の inline 指定がある
- 固定後に content テキストを増やしても、dialog の inline 幅・高さは変わらない
- `close()` して再度 `showModal()` -> 同じ固定値が残っている（再計測で上書きしない）

#### 異常系

- 一度も `showModal()` していない閉じた状態では、サイズ固定を行わない（不要な inline 固定をしない）

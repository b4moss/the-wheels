# v0.6.0 テスト仕様

対象: パッケージ公開面（`@b4moss/the-wheels` / `@b4moss/the-wheels-components` / `@b4moss/the-wheels-style`）の解決・再エクスポート・dual package（ESM + CJS）。  
**新しい Web Components の振る舞いロジックは追加しない**（既存 WC テストの回帰は `npm run test:components` で担保）。  
スタイル見た目の自動テストは行わない。

関連: [roadmap.md](../../roadmap.md) v0.6.0 / [main.md](../../main.md)

計画上の補足（完了定義）:

- components / the-wheels は Vite lib で `es` + `cjs` を出力し、`exports` で `types` / `import` / `require` を分岐する
- umbrella（`@b4moss/the-wheels`）は components API を再エクスポートし、`./style` で style 全部入り CSS を公開する
- 部分 CSS import は `@b4moss/the-wheels-style/css/*` を正式とする（umbrella は全部入り `./style` のみ保証）
- 検証はビルド後の `dist` および `package.json#exports` に対するスモーク（Vitest node 環境または `npm run test:package`）

## package.json exports（静的）

### readPackageExports(packageName)

- 各パッケージの `package.json` を読み、`exports` マップを返す（テストヘルパー）

#### 正常系

- `@b4moss/the-wheels-components` の `exports["."]` に `types` / `import` / `require`（または同等の条件キー）がある
- `@b4moss/the-wheels-components` に `exports["./assets/*"]`（または `./assets/*` 相当）がある
- `@b4moss/the-wheels` の `exports["."]` に `types` / `import` / `require` がある
- `@b4moss/the-wheels` に `exports["./style"]` がある
- `@b4moss/the-wheels-style` に `exports["."]`（全部入り CSS）と部分 import（`./css/*` 相当）がある

#### 異常系

- `exports["."]` がソースの `.ts` のみを指し `dist` を経由しない状態は不合格（v0.6.0 以降はビルド成果物を正とする）

## Build artifacts

### components / the-wheels の dist

- `npm run build`（各 workspace）後に成果物が存在する

#### 正常系

- `@b4moss/the-wheels-components` に ESM エントリ（例: `dist/index.js`）と CJS エントリ（例: `dist/index.cjs`）がある
- 同上に型宣言（例: `dist/index.d.ts`）がある
- `@b4moss/the-wheels` にも ESM / CJS / `d.ts` がある
- `@b4moss/the-wheels` の style エントリが指す CSS ファイルが存在する（例: `src/style.css` または exports 先パス）

#### 異常系

- ビルド失敗、または `dist` 欠落 -> 不合格

## ESM 解決（@b4moss/the-wheels）

### importUmbrellaEs()

- Node（または Vitest）から ESM で `@b4moss/the-wheels` を import する
- 事前に該当パッケージがビルド済みであること

#### 正常系

- `import { setPrefix, getPrefix, TwButton, TwAvatar } from '@b4moss/the-wheels'` が例外なく完了する
- `typeof setPrefix === 'function'`
- `typeof TwButton === 'function'`（カスタム要素コンストラクタ）
- `setPrefix('app'); getPrefix()` -> `"app-"`（既存 prefix 仕様どおり。テスト後は他テストへの影響に注意し、必要ならリセット）

#### 異常系

- 未ビルドで解決不能 -> スモーク前提を満たさない（ビルドを先に行う）
- 名前付きエクスポート欠落（`setPrefix` / 主要 WC クラス）-> 不合格

---

## CJS 解決（@b4moss/the-wheels）

### requireUmbrellaCjs()

- Node の `createRequire` 等で `@b4moss/the-wheels` を `require` する

#### 正常系

- `require('@b4moss/the-wheels')` がオブジェクトを返す
- 返却物に `setPrefix` / `TwButton` がある（`typeof` が function）

#### 異常系

- `require` が失敗する、または named export 相当が取れない -> 不合格

## components 単独解決

### importComponentsEs() / requireComponentsCjs()

- `@b4moss/the-wheels-components` も同様に ESM / CJS で主要 API が取れる

#### 正常系

- ESM: `setPrefix` / `TwSvgLoader` が取れる
- CJS: 同上
- `import.meta` 解決でアセット URL が必要なモジュールでも、パッケージエントリの load 自体は例外にならない（アセットファイルは `exports["./assets/*"]` で届く）

#### 異常系

- floating-ui がバンドル漏れで実行時に解決不能（external 設定ミス）-> 不合格（Node スモークでは `@floating-ui/dom` が install 済みなら load できること）

## style 再エクスポート

### resolveUmbrellaStyle()

- `@b4moss/the-wheels/style` がファイルとして解決できる

#### 正常系

- `import.meta.resolve` / `createRequire(...).resolve` / パッケージ exports 解決のいずれかで `@b4moss/the-wheels/style` が既存パスを返す
- 解決先ファイルの内容に `@import` または style パッケージへの参照が含まれる（全部入りであること）

#### 異常系

- `./style` export が無い、または解決先が存在しない -> 不合格

### 部分 CSS（style パッケージ）

#### 正常系

- `@b4moss/the-wheels-style/css/tokens`（または `exports` で定義した同等パス）が解決できる

#### 異常系

- umbrella に部分 CSS が無いこと自体は欠陥ではない（README 案内でよい）
